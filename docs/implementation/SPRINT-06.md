# Sprint 06 — Official Commerce/CMS Runtime Integration

## Implemented

- Imported a reviewed Medusa v2.19.0 backend generated by `create-medusa-app` into `apps/commerce`.
- Imported a reviewed Strapi 5.52.3 TypeScript/PostgreSQL project generated by `create-strapi` into `apps/cms`.
- Configured Medusa for PostgreSQL, Redis-backed events/workflows, CORS, JWT and cookie secrets.
- Configured Strapi to use its own `STRAPI_DATABASE_URL`/`STRAPI_DATABASE_NAME` contract rather than sharing Medusa's database schema.
- Added the initial South Africa commerce seed shape:
  - Web sales channel
  - ZAR default currency
  - South Africa region and tax region
  - Johannesburg Warehouse stock location
  - manual Standard Shipping at R85.00, with a 2–4 business-day estimate
  - Clothing category, Size/Color options, and the published Dalizebo Essential Tee
  - 100 units of inventory per seeded inventory item
- Kept Medusa's workflow input in major-unit decimals and added `toMinorUnits` at the BFF boundary. The public DTO therefore exposes R1,299.99 as `{ amount: 129999, currency: "ZAR" }`.
- Added tests for decimal-to-minor-unit conversion and ZAR DTO normalization.
- Added the commerce-owned Brand module (`brand` table), a stable `handle` business key, a migration, and a Product → Brand module link. The seed creates or reuses the `dalizebo` brand and records its ID in product metadata while the link is available for future admin workflows.
- Added a canonical `products_v1` projection for Meilisearch. Reindex now paginates Medusa, applies the same index settings, removes stale documents, and writes normalized brand/category/availability/price fields.
- Added production Dockerfiles for `apps/commerce` and `apps/cms`, with health checks and production dependency deployment.
- Added PostgreSQL first-boot provisioning for the separate `dalizebo_cms` editorial database.
- Made Medusa CLI config local to the commerce app so build, lint, migration and seed commands do not write to a user's global config directory.
- Added a local React type-resolution boundary for the Next.js storefront and enabled the supported TypeScript API checker path for the build runner.
- Updated the framework bootstrap script to use the npm path that successfully installs the official generators when pnpm build-script approval is unavailable.

## Deliberate limits

- The seed script is a first-run bootstrap and is not yet a repeat-safe migration. Stable business-key upserts are the next commerce task.
- Strapi content types, a Medusa event subscriber, Meilisearch reindex against a live catalogue, and real payment/fulfilment adapters are still explicit follow-on work.
- Marketplace, wallet, advanced loyalty, AI, native mobile and Kubernetes remain outside this release.
